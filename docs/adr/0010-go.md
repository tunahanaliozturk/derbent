# 0010. Derbent is written in Go

Date: 2026-09-27
Status: accepted

## Context

Derbent runs as many short-lived and long-lived processes on the user's machine. Every agent session
starts its own `derbent mcp`, which in turn supervises that session's downstream servers. The Claude
Code hook of milestone 4 is worse: Claude Code starts `derbent gate` once for every tool call it
makes, so every shell command and file edit waits for that process to start, decide and exit. The
program has to install on Windows, macOS and Linux without asking the user for a language runtime, and
its release binaries have to be reproducible.

Python was the other serious candidate. Its MCP SDK is the most used one, it is quicker to write, and
Textual is a good terminal UI library. .NET with Native AOT would also give one fast-starting binary and
has an official MCP SDK.

## Decision

Go 1.27, with the official MCP Go SDK, `modernc.org/sqlite` (ADR 0008) and Bubble Tea for the UI.

- A Go binary starts without loading an interpreter or importing a package tree, which matters for a
  process that runs once per tool call.
- One static binary per platform, built without cgo, installs with `go install` or a download and
  needs nothing else on the machine. Builds with `-trimpath` can be checked for identical hashes.
- Supervising several downstream servers, polling for approvals and cancelling cleanly are plain
  goroutines and contexts, and goleak holds every test to leaving none behind.
- The tools Derbent sits among are largely Go already: the GitHub MCP server, `gh`, Docker.

## Consequences

Features that lean on machine learning, such as the local embeddings on the Later list, have fewer
libraries to choose from in Go than in Python. The per-call cost of the hook is measured in milestone 5
rather than assumed.
